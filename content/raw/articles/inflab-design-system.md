# 인프런 디자인 시스템 구축기 (a.k.a. 4개의 디자인시스템 관리하기)

원문: 인프랩 실Log — 프로덕트 디자인 파트 인터뷰 형식

## 핵심 요약

### 배경
- 21~22년 디자인 파트 1인 → 5인으로 확장
- 서비스 파편화 심화: 디자인 시스템에 등록 안 된 개별 디자인 증가
- 디자인-개발 전달 시 상태별 명세 누락, 기준 불명확 → 수정 비용 증가
- 디자인 시스템 도입이 자연스럽게 필요해짐

### 구축 방식: 외부 오픈소스 라이브러리 활용
- 0부터 만드는 건 비효율 → 기존 잘 만들어진 오픈소스 활용
- 라이브러리 선정 기준: 1) 커스텀 제약이 적은지 2) 개발 커뮤니티 활성화 3) 생산성 저하 없는지
- VanillaJS → **부트스트랩(Bootstrap)**
- ReactJS → **만타인(Mantine)**
- 피그마 디자인 키트 존재 여부 확인, 두 환경(VanillaJS/React) 모두 지원 여부 확인

### 4개의 디자인 시스템
1. **기존 인프런 디자인 시스템** (구버전, 폐지 대상)
2. **부트스트랩** (VanillaJS 페이지용)
3. **만타인** (ReactJS 페이지용)
4. **랠릿** (별도 서비스, 임시 시스템)

→ 최종 목표: 기존 시스템 폐지, 부트스트랩 + 만타인 2개로 통합

### 핵심 교훈
- 스타트업은 디자인 시스템에만 리소스 할애 불가 → 외부 라이브러리 사용이 효율적
- 대기업은 자체 구축, 전담 디자인 플랫폼 팀 별도 운영
- 자체 구축해도 한꺼번에 적용이 아닌, 페이지 디자인 시마다 점진적 적용
- **전사 싱크업 필수**: 디자인 파트 + 프론트엔드 파트 + CTO가 함께 논의
- 디자인 시스템은 디자이너만의 도구가 아님 → 개발팀과의 싱크가 핵심
