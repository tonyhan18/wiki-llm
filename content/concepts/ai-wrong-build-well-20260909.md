# AI 개발의 진짜 위험: 잘못된 생각을 너무 잘 구현

## 정의
AI 코딩 에이전트의 진짜 위험은 "못 만드는 게 아니라, 잘못 생각한 걸 너무 잘 만들어준다"는 것. 인간의 검증 없이 AI가 코드를 빠르게 생산할 때 설계 오류가 확대 재생산되는 현상.

## 핵심 인사이트

### 위험의 구조
- AI는 잘못된 가정도 오류 메시지 없이 구현
- 직관적으로 맞아 보이는 요구사항이 실제로는 구조적 오류를 포함
- 속도가 빠를수록 인간이 검증할 틈이 줄어듦
- "구조부터 확인하고 결과만 보고 멈춰" — 검증 우선 워크플로우 필요

### Quiz Gate: 코드 리뷰 품질 도구
- git diff 기반 퀴즈로 AI 작성 코드의 컨텍스트 이해 강제
- 머지 전 코드 변경점 검증 → AI 코딩 시대의 품질 관리
- AI가 작성한 코드를 팀이 확실히 이해하는 것이 생산성의 핵심
- 인간 개입 지점이 "지시"에서 "검토"로 이동

### 프로그래밍 동기와 AI 수용도
- 제품 중심(수단적): AI 위임 = 효율 → 수용적
- 과정 중심(내재적): AI 위임 = 정체성 위협 → 저항적
- [[programming-as-art-20260909|프로그래밍은 예술이다]]: 동기에 따라 AI 의미가 다름
- AI 시대에 인간 코더에게 남는 것: 설계·검증·안목

## 미해결 질문
- AI 코딩 품질 관리를 위한 최소 검증 프로세스는 무엇인가?
- 검증 도구(Quiz Gate 등)가 팀 생산성을 실제로 향상시키는가?
- 인간의 설계 역량이 AI 코딩 속도를 따라갈 수 있는가?
