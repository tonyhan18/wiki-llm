# AI 시대의 코드 품질 측정: 조잃함은 어떻게 측정할까?

## 정의
AI가 테스트를 통과하는 코드를 만들 수 있어도 불필요한 추상화, 중복, 나쁜 설계를 피하지 못하며, 코드의 조잃함(crudiness)을 객관적으로 측정할 방법이 부재하다는 근본 문제. 기능 정상 작동은 테스트로 검증 가능하지만 코드 품질은 측정 불가하여, AI 코딩 시대의 새로운 병목은 품질 검증 메트릭 부재.

## 핵심 인사이트

### 테스트 통과 ≠ 좋은 코드
- AI가 생성한 코드는 테스트를 통과하지만 품질이 낮을 수 있음
- 불필요한 추상화, 중복, 나쁜 설계 — 기능엔 영향 없지만 유지보수성 붕괴
- 기능 추가 시마다 코드가 불어나면 사람도 에이전트도 관리 불가
- [[astra-coding-paradox-20260911|GPT-6 Astra 코딩의 역설]] — 75,000줄 코드의 관리 가능성

### 측정 불가능성의 문제
- 기능 정상 작동 → 테스트로 자동 검증 가능
- 코드 조잃함 → 객관적 메트릭 부재 (복잡도, 우아함, 설계 품질)
- "측정할 수 없으면 관리할 수 없다" — AI 코딩 시대의 품질 관리 딜레마
- [[ai-wrong-build-well-20260909|AI 개발의 진짜 위험]] — 잘못된 생각을 너무 잘 구현

### AI 에이전트 관리 불가 시나리오
- 코드가 불어나면 AI 에이전트도 컨텍스트 한계로 관리 불가
- [[proliferate-parallel-agent-ide-20260910|Proliferate: 다중 에이전트 병렬 코딩 IDE]] — 병렬 에이전트 환경에서 더 심각
- [[build-vs-buy-ai|Build vs Buy]] — "3년 차에는 누가 패치하는가" 문제의 연장
- 코드 베이스 크기 vs 관리 능력의 비대칭 성장
