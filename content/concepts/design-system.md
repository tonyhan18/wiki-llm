# 디자인 시스템 구축

## 개념
서비스 규모가 커지고 팀이 확장될 때, 디자인 일관성과 재사용성을 위해 시스템화하는 방법론.

## 핵심 인사이트

### 도입 배경
- 팀원 확장 → 서로 다른 스타일 충돌 → 유저 학습 비용 증가
- 디자인-개발 전달 시 기준 불명확 → 수정 비용 증가
- 제품 출시 속도를 위해 업무 효율 필수

### 구축 전략: 외부 라이브러리 활용
- 0부터 만드는 건 비효율 → **기존 오픈소스 라이브러리를 커스텀**
- 선정 기준: 1) 커스텀 제약이 적은지 2) 커뮤니티 활성화 3) 생산성 저하 없는지
- 환경별 라이브러리: VanillaJS → 부트스트랩, ReactJS → 만타인
- 피그마 디자인 키트 존재 여부 확인 필수

### 점진적 적용
- 한꺼번에 적용이 아닌, 페이지 디자인 시마다 점진적 적용
- **전사 싱크업 필수**: 디자인 파트 + 프론트엔드 파트 + CTO가 함께
- 디자인 시스템은 디자이너만의 도구가 아님 → 개발팀과의 싱크가 핵심

### 조직 규모별 차이
- **스타트업:** 외부 라이브러리 사용 (리소스 한계)
- **대기업:** 자체 구축, 전담 디자인 플랫폼 팀 운영
