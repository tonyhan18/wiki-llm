# GPT-6 Astra 코딩의 역설

## 개요
GPT-6 Astra는 컴퓨터 사용과 이미지 이해에서 뛰어난 능력을 보이지만, 실제 소프트웨어 개발에서는 함께 일하기 더 어려워졌다. 높아진 비용에 걸맞은 성과도 체감하기 어렵다. 가상 스레드와 렉시컬 스코프를 갖춘 Python을 만들도록 맡겼으나, 35시간 동안 7만 5,000줄 코드를 생성했지만 결과물 품질에 대한 의문이 제기되었다.

## 핵심 내용
- **능력 향상의 역설**: 더 똑똑해졌지만 협업은 더 어려워짐
- **양 vs 질**: 35시간 75,000줄 코드 생성 — 양은 압도적이나 질 검증 불확실
- **비용-성과 괴리**: 높아진 토큰 비용 대비 체감 성과 부족
- **능력 분리**: 컴퓨터 사용·이미지 이해 능력 ≠ 소프트웨어 개발 능력

## 의미
이 사례는 [[gpt-6-astra]]의 능력 평가에 중요한 데이터 포인트를 추가한다. [[gpt6-astra-token-economics-20260908]]에서 예견된 토큰 비용 문제가 현실화된 것이며, [[cognition-swe-2-20260911]]의 비용 효율적 코딩 AI 모델 접근과 대조를 이룬다. [[build-vs-buy-ai]]의 "3년 차에는 누가 패치하는가" 질문이 더욱尖锐해진다.

[[ai-wrong-build-well-20260909]]의 경고와 연결: AI가 잘못된 가정도 너무 잘 구현하는 문제가 대규모 코드 생성에서 더 위험해진다. [[programming-as-art-20260909]]의 관점에서, 과정 중심 프로그래밍의 가치가 AI 대량 생성 시대에 오히려 부각된다.

## 시사점
- 에이전트 코딩의 현실적 한계: 능력 ≠ 실용성
- 비용 효율성이 코딩 AI 경쟁의 새 전선 ([[cognition-swe-2-20260911]])
- 인간 검증 역할의 중요성 증대 — [[ai-safety-alignment]]의 실용적 적용
- 75,000줄은 관리 불가능 — 모듈화·검증 게이트 필요
