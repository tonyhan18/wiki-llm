# Build vs Buy: AI 시대의 자체 개발 의사결정

## 정의
AI가 소프트웨어의 초기 개발 비용은 크게 낮췄지만, 수년간 유지보수와 보안, 장애 대응을 책임지는 운영 비용까지 없애지는 못함. "만드는 편이 더 싼가"가 아니라 "무엇을 앞으로도 계속 책임질 것인가"가 핵심 질문.

## 핵심 인사이트

### 만드는 비용 vs 운영하는 비용
- AI가 코드 작성 비용을 낮췄지만, 보안 패치, 취약점 대응, 장애 처리는 여전히 인간 책임
- 자체 개발의 실패는 첫 분기가 아니라 18개월 뒤에 드러나기 쉬움
- 처음 만들던 사람이 떠나고, 코드를 처음 보는 사람이 시스템을 익혀야 함

### 직접 만들기 전 확인할 네 가지
1. **피해 범위** — 장애나 침해가 발생하면 무엇이 영향을 받는가
2. **장기 운영 책임** — 향후 수년간 패치와 보안 대응을 누가 맡는가 (팀이 아닌 개인의 이름)
3. **사업 차별화** — 고객에게 중요한 개선인가, 단지 취향에 맞는가
4. **교체할 경로** — 1년 뒤 외부 제품이 나오면 부담 없이 버릴 수 있는가

### "3년 차에는 누가 패치하는가"
- 회의에서 하나만 묻는다면 이 질문을 물어야 함
- 답이 없다면 의사결정은 끝나지 않은 상태

### 직접 만들 가치가 커진 영역
- 작고 범위가 제한된 맞춤형 개발은 AI 시대에 더 합리적
- 사업을 차별화하는 기능은 만들고, 단순히 안정적으로 작동해야 하는 기능은 구매
- 회사 밖에서는 알아차리지 못할 소수 예외만 해결한다면 자체 개발 정당화 어려움

## 미해결 질문
- AI가 패치 작성도 도와주는 시점에서, 유지보수 비용은 어디까지 줄어드는가?
- 자체 도구의 기술 부채를 AI가 상쇄할 수 있는 임계점은?
